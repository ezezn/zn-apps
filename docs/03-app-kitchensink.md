# Kitsinksink (Blueprint for New Apps)

This document describes the **kitchensink** application, which acts as the blueprint for new apps and as the icon catalog.

## 1. Overview

- **Name**: `kitchensink`
- **Role**: Documentação de componentes e **catálogo completo de ícones**.
- **Stack**: Vue 3 + Vite + Vue Router + `vite-plugin-pwa`.
- **Dependencies**:
  - `@zn-apps/ui-core` (`@zn-apps/ui-core`: `"*"`)
  - `vue` (`^3.5.34`)
  - `vue-router` (`^4.6.4`)
- **DevDependencies**:
  - `@vitejs/plugin-vue` (`^5.0.0`)
  - `vite` (`^5.0.0`)
  - `vite-plugin-pwa` (`^0.20.0`)

## 2. Architecture

Kitchensink is an autonomous SPA. It consumes **only** `shared/ui-core` and never shares Pinia state with other apps.

- The UI is composed of `ZnApp` (theme wrapper), `ZnScreen` (layout), `ZnSection` (grouped content) and the concrete components (`ZnButton`, `ZnCard`, `ZnSwitch`, `ZnIcon`, `ZnBox`, `ZnRow`, `ZnNavigationLayout`).
- Icons are not bundled as static PNG/SVG files. The app references them through `ZnIcon`, which resolves a `<symbol>` from a **generated sprite**.
- The app ships its own `icon-profile.json` with the **full catalog** (every Material Design icon) plus a small `manual` set of commonly used icons.

## 3. Icon pipeline

```
shared/ui-core/scripts/generate-icons.mjs --profile app:kitchensink
```

The script:

1. Reads the requested profile (here `app:kitchensink`).
2. Loads every family (`filled`, `outlined`, `round`, `sharp`, `two-tone`) from the Material Design Icons collection.
3. Filters each family down to the names in the profile.
4. Generates a **sprite + names module** per family and writes them to `kitchensink/dist/`:

   ```
   dist/
   ├── zn-icon-filled.svg                       ← filled family sprite
   ├── zn-icon-names-filled.js                  ← names for the filled family
   ├── zn-icon-outlined.svg
   ├── zn-icon-names-outlined.js
   └── …
   ```

Each `zn-icon-names-*.js` module looks like:

```js
// Generated by generate-icons.mjs
export default ["00_trigger", "1000mile", "ac_unit", "access_alarm", …]
```

`ZnIcon` calls `loadIconFamily(family)` the first time an icon of a family appears; the sprite is then injected **once** into the document and reused by every `<use href="#zn-icon-filled-…">` reference.

## 4. Running the icon pipeline

```bash
# 1) Scan the app for ZnIcon usages and refresh icon-profile.json
npm run scan:icons

# 2) Generate the app-specific chunk (the script never fails the pipeline on CI)
npm run generate:icons

# 3) Build the app (the generated chunk is copied into dist/ automatically)
npm run build
```

The whole command is:

```bash
npm run build:icons && npm run build
```

## 5. File layout

| Path | Purpose |
|---|---|
| `kitchensink/src/App.vue` | Root component, theme toggle, layout shell |
| `kitchensink/src/main.js` | App bootstrap + router |
| `kitchensink/src/router/index.js` | Vue Router definition |
| `kitchensink/src/views/*.vue` | All feature pages |
| `kitchensink/scripts/scan-icons.mjs` | Scans `<ZnIcon name="…">` and updates `icon-profile.json` |
| `kitchensink/vite.config.js` | Vite + PWA config (alias to the shared library source) |
| `kitchensink/icon-profile.json` | Scanned + manual icon names |

## 6. Testing

Run the unit tests with Vitest:

```bash
npm run test:run
```

Tests live in `kitchensink/src/__tests__/`. The shared setup (`vitest.setup.js`) mocks `window.matchMedia` and `IntersectionObserver`, which are used by `ZnApp` and `ZnScreen`.

## 7. Deployment

The app is a standard Vite SPA. The production build outputs to `dist/`, and `vite-plugin-pwa` generates the service worker (`sw.js`) that is responsible for precaching. When deployed to a subpath (e.g. `/zn-apps/kitchensink/`), set `base` accordingly in `vite.config.js`.

## 8. Legacy templates to ignore

`pwa-app1` and `pwa-app2` are legacy templates scheduled for removal. New apps must not be created from them.
